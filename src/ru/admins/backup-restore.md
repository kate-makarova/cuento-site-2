<p class="docs-lead">Cuento автоматически делает резервные копии базы данных на Google Drive по настраиваемому расписанию. Резервные копии — это обычные SQL-дампы: читаемые, восстанавливаемые без специального инструментария и автоматически удаляемые по лимиту, чтобы Drive не переполнялся.</p>

## Как это работает

Планировщик резервного копирования работает в фоне внутри процесса Cuento. Каждый час он проверяет, пора ли делать резервную копию — исходя из настроенной частоты. Когда приходит время, запускается `mysqldump` с флагом `--single-transaction`, и получившийся `.sql`-файл загружается в папку **Cuento Backups** на вашем Google Drive. Файлы называются `backup_ГГГГ-ММ-ДД_ЧЧ-ММ-СС.sql`. После каждой загрузки планировщик удаляет старые файлы, оставляя лишь N последних, которые вы указали.

Для работы резервного копирования нужно три значения в административной панели: **Client ID**, **Client Secret** и **Refresh Token** из вашего OAuth2-приложения Google. Шаги ниже объясняют, как их получить.

---

## Шаг 1 — Создайте проект в Google Cloud

1. Перейдите на [console.cloud.google.com](https://console.cloud.google.com/) и войдите под Google-аккаунтом, который будет владеть хранилищем Drive.
2. Нажмите на выбор проекта вверху → **Новый проект**. Назовите его как угодно (например, `cuento-backup`).
3. Выбрав новый проект, перейдите в **API и сервисы → Библиотека**.
4. Найдите **Google Drive API** и нажмите **Включить**.

---

## Шаг 2 — Создайте учётные данные OAuth 2.0

1. В том же проекте перейдите в **API и сервисы → Учётные данные**.
2. Нажмите **Создать учётные данные → Идентификатор клиента OAuth**.
3. Если потребуется настроить экран согласия:
   - Выберите тип **Внешний** (или **Внутренний** для аккаунта Google Workspace).
   - Заполните обязательные поля: название приложения и контактный email. Добавлять права доступа и тестовых пользователей на этом этапе не нужно — приложение останется в режиме тестирования.
4. На экране создания учётных данных укажите **Тип приложения: Приложение для ПК**. Дайте любое имя и нажмите **Создать**.
5. В диалоговом окне появятся ваши **Client ID** и **Client Secret**. Скопируйте оба — они понадобятся чуть позже.

---

## Шаг 3 — Получите refresh token

Cuento использует долгосрочный refresh token, чтобы загружать резервные копии без повторной аутентификации. Проще всего получить его через Google OAuth2 Playground:

1. Откройте [developers.google.com/oauthplayground](https://developers.google.com/oauthplayground/).
2. Нажмите на шестерёнку (⚙) в правом верхнем углу.
3. Поставьте галочку **Use your own OAuth credentials** и вставьте **Client ID** и **Client Secret** из шага 2.
4. В левом столбце найдите **Drive API v3** и выберите область видимости `https://www.googleapis.com/auth/drive`. Нажмите **Authorize APIs**.
5. Откроется окно входа Google. Войдите под тем же аккаунтом, который владеет проектом.
6. Нажмите **Exchange authorization code for tokens**.
7. Скопируйте **Refresh token** из ответа. Он начинается с `1//`.

> **Держите этот токен в тайне.** Любой, у кого есть Client ID, Client Secret и Refresh Token, получит доступ к вашему Drive.

---

## Шаг 4 — Настройте резервное копирование в административной панели

Перейдите в **Администрирование → Резервное копирование**. Введите полученные данные:

| Поле | Значение |
|---|---|
| **Client ID** | Из шага 2 |
| **Client Secret** | Из шага 2 |
| **Refresh Token** | Из шага 3 |
| **Folder ID** | Оставьте пустым для автоматически созданной папки **Cuento Backups**, или вставьте ID конкретной папки Drive |
| **Частота** | `daily` (ежедневно), `weekly` (еженедельно) или `monthly` (ежемесячно) |
| **Хранить** | Количество файлов резервных копий для хранения (старые удаляются после каждой новой загрузки) |
| **Включено** | Переключатель для запуска планировщика |

Нажмите **Сохранить настройки**. Чтобы сразу проверить подключение, нажмите **Запустить резервное копирование** — резервная копия должна появиться в списке в течение нескольких секунд.

---

## Скачивание резервной копии

В административной панели отображается список всех резервных копий в папке Drive с временными метками. Нажмите на любую запись, чтобы скачать `.sql`-файл прямо на компьютер.

---

## Восстановление из резервной копии

### Когда форум работает

Если форум доступен, можно восстановить через административную панель:

1. Перейдите в **Администрирование → Резервное копирование → Восстановление**.
2. Загрузите `.sql`-файл (скачанный с Drive или полученный при ручном экспорте).
3. Бэкенд передаёт файл в `mysql` и возвращает результат по завершении импорта.

**Внимание:** это перезапишет текущую базу данных. Все данные, добавленные после создания резервной копии, будут утеряны.

### Когда форум недоступен

Если сайт не открывается и нужно восстановить базу вручную, воспользуйтесь Cuento CLI:

1. Скачайте `.sql`-файл с Google Drive напрямую (через drive.google.com).
2. Запустите CLI, перейдите в **Database** → **Restore from file** и укажите путь к `.sql`-файлу.
3. CLI подключится к серверу по SSH, скопирует файл и запустит импорт через `mysql`.

### Ручной импорт через SSH

Если предпочитаете сделать это самостоятельно:

```bash
# Скопируйте резервную копию на сервер
scp backup_2026-01-01_12-00-00.sql user@ваш-сервер:/tmp/

# Подключитесь по SSH и запустите импорт
ssh user@ваш-сервер
mysql -u <пользователь_бд> -p<пароль_бд> <имя_бд> < /tmp/backup_2026-01-01_12-00-00.sql
```

---

## Ручной экспорт (без Google Drive)

Если нужен разовый SQL-дамп без настройки Google Drive, в административной панели есть кнопка **Экспортировать** в разделе **Администрирование → Резервное копирование**. Она скачивает свежий `mysqldump` прямо в браузер.
