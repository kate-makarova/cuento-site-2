<p class="docs-lead">Кастомные поля позволяют добавлять дополнительную информацию к анкетам персонажей, профилям персонажей, заголовкам эпизодов и объявлениям о желаемых персонажах — без единой строки кода. Вы настраиваете поля в панели администратора, и платформа автоматически создаёт нужные столбцы в базе данных.</p>

## Какие сущности поддерживают кастомные поля

Кастомные поля доступны для четырёх типов сущностей:

| Сущность | Что затрагивает |
|---|---|
| **Анкета персонажа** | Основная анкета, которую заполняет каждый игрок |
| **Профиль персонажа** | Вторичный информационный блок, отображаемый рядом с анкетой |
| **Заголовок эпизода** | Описание и метаданные в верхней части каждого эпизода |
| **Желаемый персонаж** | Объявление, которое публикуется при поиске конкретного персонажа |

Каждый тип сущности имеет собственный независимый шаблон. Изменения в шаблоне анкеты персонажа не влияют на заголовки эпизодов, и наоборот.

## Открытие редактора шаблонов

Для каждого типа сущности в панели администратора есть отдельная страница редактора:

- **Администратор → Шаблон персонажа** — поля анкеты персонажа
- **Администратор → Шаблон профиля персонажа** — поля профиля персонажа
- **Администратор → Шаблон эпизода** — поля заголовка эпизода
- **Администратор → Шаблон желаемого персонажа** — поля объявления о желаемом персонаже

## Имена полей

У каждого поля два имени.

**Machine name (системное имя)** — используется внутри системы как имя столбца в базе данных. Допускаются только строчные буквы латиницы, цифры и знаки подчёркивания (`a–z`, `0–9`, `_`). После сохранения поля с этим именем менять его нельзя — изменение расценивается как удаление старого поля и создание нового, все данные теряются.

**Human name (отображаемое имя)** — метка, которую видят пользователи в формах и на странице. Можно менять в любое время без потери данных.

## Типы полей

**Тип поля** определяет, как значение хранится в базе данных. **Тип контента** определяет, как оно представлено пользователям в форме.

### Текстовые поля

| Тип контента | Что показывается |
|---|---|
| `short_text` | Однострочное текстовое поле |
| `long_text` | Многострочная область с поддержкой BBCode-форматирования |

Используйте `short_text` для имён, заголовков и кратких меток. Используйте `long_text` для описаний, биографий и всего, что занимает несколько абзацев или требует форматирования.

### Числовые поля

| Тип контента | Хранение |
|---|---|
| `number` | Целое число |
| `decimal` | Десятичное число — до двух знаков после запятой |

### Поле даты

Тип контента `date` показывает выбор даты. Даты хранятся внутри системы и форматируются для отображения в соответствии с локалью пользователя.

### Поля изображений

| Тип контента | Поведение |
|---|---|
| `image` | Загрузка изображения в исходном размере |
| `cropped_image` | Загрузка изображения с принудительной обрезкой до заданных пикселей |

Для `cropped_image` укажите **Ширину** и **Высоту** в пикселях. Все загружаемые изображения для этого поля будут обрезаны до точно указанных размеров.

### Свободный формат даты

Тип `free_format_date` — это кастомная система дат для ситуаций, когда реальный календарь не подходит: например, игровая дата, название сезона или год в вымышленной эпохе. Вы задаёте строку формата с плейсхолдерами; пользователи заполняют их при редактировании сущности. Значения поддерживают сортировку, поэтому списки сущностей можно упорядочить по этому полю.

### Select-поля (выбор из списка)

Select-поле позволяет пользователям выбрать одно значение из заданного вами фиксированного списка. Доступны два стиля отображения:

| Тип контента | Вид |
|---|---|
| `dropdown` | Выпадающий список |
| `radiobox` | Группа радиокнопок |

При выборе типа select появляется редактор **Опций**. У каждой опции есть числовой ключ (используется внутри) и текстовая метка (показывается пользователям). Добавляйте и удаляйте опции по необходимости. Изменение или удаление ключа существующей опции повлияет на все сущности, у которых уже сохранено это значение.

## Порядок полей

У каждого поля есть числовой **порядок**, который определяет его место в форме и на странице отображения. Меньшее число — выше. Поля с одинаковым порядком сортируются по machine name.

## Блоки

Блоки позволяют группировать связанные поля под общим заголовком. У блока есть название (отображается как заголовок раздела) и список принадлежащих ему полей. Поля, не включённые ни в один блок, отображаются в несгруппированном разделе по умолчанию.

Переставлять блоки и менять состав полей в них можно в любое время — это изменение только презентационное и не влияет на хранение данных.

## Блок-переключатели

Блок-переключатель — это тумблер, который каждая отдельная сущность может включить или выключить, чтобы показать или скрыть группу полей. Например, если у части персонажей есть блок «Продвинутые навыки», а у других нет, можно добавить переключатель — и игрок каждого персонажа сам решит, включать его или нет.

У каждого переключателя есть machine name, метка и список полей, которыми он управляет. Когда игрок отключает переключатель на своей сущности, эти поля скрываются из просмотра (значения сохраняются, просто не отображаются).

## Изменение типа существующего поля

Если вы меняете **тип поля**, у которого уже есть данные, платформа предупредит вас перед сохранением. Переход, например, с `text` на `string` обрежет все сохранённые значения длиннее 255 символов. Изучите предупреждение и подтвердите только в том случае, если вы уверены, что существующие данные можно потерять или обрезать.

Изменение **отображаемого имени**, **порядка** или **блока** существующего поля всегда безопасно.
