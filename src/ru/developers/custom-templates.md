<p class="docs-lead">Cuento позволяет переопределять HTML-структуру отдельных Angular-компонентов во время сборки — не затрагивая шаблоны по умолчанию в репозитории. Это позволяет каждому форуму иметь собственный визуальный макет ключевых страниц, оставаясь на основной кодовой базе.</p>

## Как это работает

`npm run build` запускает `custom-templates.plugin.mjs` вместо прямого вызова `ng build`. Плагин читает JSON-файл, специфичный для сайта, временно копирует каждый кастомный файл поверх его версии по умолчанию, запускает сборку Angular, а затем восстанавливает оригиналы — независимо от результата сборки.

**Сервер разработки не затронут** — `npm start` всегда использует шаблоны по умолчанию. Кастомные шаблоны применяются только при продакшен-сборке.

## Сохранить vs. Опубликовать

В административной панели есть два разных действия.

**Сохранить** записывает HTML шаблона в базу данных как именованную версию — это не влияет на живой сайт и может выполняться многократно.

**Опубликовать** делает три вещи атомарно: фиксирует файл шаблона в GitHub как активный `*.custom.component.html`, обновляет `src/environments/custom_templates.json` на GitHub, и этот коммит в ветку `release` запускает GitHub Actions CI, который выполняет `npm run build` и автоматически деплоит.

Сохранение — это черновик. Публикация — это деплой. Вы можете сохранить несколько версий и выбрать, какую опубликовать в любой момент. `custom_templates.json` никогда не редактируется вручную — им управляет бэкенд.

## Доступные компоненты

Следующие компоненты поддерживают кастомные шаблоны. Каждый кастомный шаблон является валидным Angular-шаблоном, скомпилированным как часть существующего класса компонента — он может использовать только привязки и директивы, объявленные или импортированные в этом компоненте.

### Шапка

Файл: `src/app/components/header/header.custom.component.html`

Переопределяет общую шапку сайта. Ключевые привязки: `title()` (название сайта), `currentUser()`, `authService.isAuthenticated()`, `headerPanelHtml()` (HTML-панель, отображаемая бэкендом). Включите элемент `#header-widget-panel` с `[innerHTML]="headerPanelHtml()"` и директивой `appRouterLinks`. Доступные дочерние компоненты: `app-navlinks`, `app-ulinks`, `app-notifications`.

### Категория

Файл: `src/app/components/category/category.custom.component.html`

Переопределяет блок категории на главной странице форума. Получает входные данные `category` с полями `.name` и `.subforums[]`. Каждый подфорум предоставляет id, название, описание, счётчики тем/постов, индикатор непрочитанного и метаданные последнего поста.

### Статистика в подвале

Файл: `src/app/components/footer-statistics/footer-statistics.custom.component.html`

Переопределяет блок статистики в нижней части страницы. Доступные сигналы: `board()` (настройки форума и счётчики), `activeUsers()`, `activeGuests()`, `recentUsers()`, `recentCharacters()`, `recentMode()`. Вызовите `setRecentMode(m)` для переключения между списками пользователей и персонажей.

### Заголовок эпизода

Файл: `src/app/components/episode-header/episode-header.custom.component.html`

Переопределяет область заголовка на страницах эпизодов. Предоставляет объект `episode` (название, статус, участвующие персонажи и маски, возрастной рейтинг), `customFields[]` и вспомогательный метод `getField(machineName)`. Защита `@if (episode != null)`. Дочерний компонент: `app-field-display`.

### Заголовок анкеты персонажа

Файл: `src/app/components/character-sheet-header/character-sheet-header.custom.component.html`

Переопределяет заголовок на страницах анкет персонажей. Предоставляет объект `character` (имя, аватар, статус, фракции, количество эпизодов), `customFields[]` и `getField(machineName)`. Методы административных действий и сигнал `canSeeAdminBlock()` доступны для условного отображения кнопок модерации. Защита `@if (character != null)`.

### Заголовок желанного персонажа

Файл: `src/app/components/wanted-character-header/wanted-character-header.custom.component.html`

Переопределяет заголовок на страницах желанных персонажей. Предоставляет `wantedCharacter` (имя, статус, состояние занятия, фракции, связи), `customFields[]` и `getField(machineName)`. Защита `@if (wantedCharacter != null)`.

### Карточка желанного персонажа

Файл: `src/app/components/wanted-character-card/wanted-character-card.custom.component.html`

Переопределяет отдельную карточку в списке желанных персонажей. Предоставляет полный объект `wantedCharacter`, состояние `expanded`, `canRevoke`, `isAuthenticated`, `fields[]` и `getField(machineName)`. Используйте выходные данные `(expand)`, `(collapse)`, `(claim)` и `(revoke)` для подключения интерактивных действий.

## Добавление нового кастомного шаблона

Чтобы сделать компонент переопределяемым, создайте файл `*.custom.component.html` рядом с шаблоном по умолчанию и зарегистрируйте его в срезе `frontendComponentDefs` в файле `src/Controllers/frontend_template.go` на бэкенде. После регистрации компонент появится в административной панели, где шаблоны можно писать, сохранять и публиковать. Бэкенд берёт на себя коммит файлов в GitHub и обновление списка активных компонентов — ручное редактирование JSON или ручной запуск сборки не требуются.
